    [42 Exam Rank 03] Complete Guide to All 14 Python Questions | Includes Original Text, English Translation, Diagrams, and Solutions for 'sorted()' Restrictions

    The first exam you take in the new 42 curriculum (Python) is Exam Rank 03. It is a test where you write short functions to manipulate strings and lists, with a pool of 14 questions in total. While the problems themselves are small enough to be written in a few minutes each, the scary part of this exam is getting tripped up by forbidden functions like 'sorted() forbidden' and subtle conditions in the problem statement for which you can lose points.

    Even I encountered a problem during practice where "four examples passed, but one didn't match" (the cryptic_sorter I will introduce later). Moreover, this problem came with the troublesome bonus that the expected answer was reversed depending on the version of the question.

    In this article, I will explain all 14 questions of Rank 03 in the following format:

    1. Problem Statement (Original): The English problem statement displayed during the exam

    2. Japanese Translation: The Japanese translation of the problem statement below the original text

    3. Diagram: Processing Flow: A diagram showing what the code does step-by-step using a specific input

    4. Solution Code: The code I actually used to solve it

    5. Tips: Pitfalls and the 'patterns' used for that problem

    About the solution code in this article

    • The code is the solution from my practice repository (anju0618/42_python_exam)

    • I have verified all questions by actually running the input/output examples from the problem statements. For the ones that didn't match (cryptic_sorter), I have included the cause and the corrected version

    • The solutions are written **without using `sorted()`, `.sort()`, `set()`, `Counter`, etc.** This is because what is forbidden on the actual exam varies by problem, so being able to 'write everything by hand' is the safest approach

    • The problem statements may have different function names or minor specifications depending on the campus or the time of year. I have noted the differences from the version I practiced with in the 'Differences from the version I practiced' section for each problem. Always read the problem statement on the exam screen during the actual test

    List of all 14 questions

    | Level | Problem | Difficulty | In a nutshell |
    |---|---|---|---|
    | 1 | bracket_validator | easy | Check bracket matching with a stack |
    | 1 | cryptic_sorter | easy | Sort with 4-level conditions (sorted forbidden) |
    | 2 | echo_validator | easy | Palindrome check with only English letters |
    | 2 | mirror_matrix | easy | Reverse each row |
    | 3 | hidenp | medium | Subsequence check (2 pointers) |
    | 3 | inter | medium | Common characters without duplicates |
    | 3 | number_base_converter | medium | Mutual conversion between bases 2-36 |
    | 3 | pattern_tracker | medium | Count pairs where 'one larger number' is adjacent |
    | 4 | anagram | medium | Anagram check ignoring spaces and case |
    | 4 | shadow_merge | medium | Merge two sorted lists |
    | 4 | string_permutation_checker | medium | Permutation check distinguishing case and spaces |
    | 5 | string_sculptor | hard | Convert only English letters alternating between small and large |
    | 5 | twist_sequence | hard | Rotate array to the right by k |
    | 6 | whisper_cipher | hard | Caesar cipher |

    Even though they are labeled 'hard', Levels 5-6 are actually not that difficult. The one where you are most likely to lose points is Level 1's cryptic_sorter.

    Exam flow: Increasing the level one question at a time

     Level 1 ──合格──▶ Level 2 ──合格──▶ Level 3 ──▶ … ──▶ Level 6 ──▶ 試験合格
    │                 │
  不合格            不合格
    ▼                 ▼
 同じレベルの別の問題（または同じ問題）にもう一度挑戦

    At each level, one question is randomly selected from the problems of that level (detailed rules such as how to handle failures vary depending on the campus and exam settings). Therefore, the basic strategy is to build up the state where you can 'reliably write the code for both questions at Level 1' starting from Level 1.

    The 4 patterns common to all 14 questions

     ┌────────────────────┬─────────────────────────────────────────┐
 │ 型                 │ 使う問題                                │
 ├────────────────────┼─────────────────────────────────────────┤
 │ スタック           │ bracket_validator                       │
 │ 2ポインタ          │ hidenp, shadow_merge                    │
 │ 辞書で個数を数える │ anagram, string_permutation_checker     │
 │ ord()と % 26       │ whisper_cipher                          │
 └────────────────────┴─────────────────────────────────────────┘

    If you grasp these four points first, the rest is just a matter of "turning the problem conditions into code one by one."

    When to take it: Once you pass the circle, take the exam immediately!!

    As soon as you pass the circle assignments, take the exam immediately, even if you don't feel ready. You can retake the exam as many times as you want, but the dates are fixed. You can take the first attempt with the mindset of "scouting out what kind of questions will appear." Even if you fail, the questions that appeared and your own weaknesses will become clear, which will drastically increase your chances of passing the next time.

    From here on, I will explain the tricks for when you get stuck during the actual exam (such as looking at the traceback and hardcoding with if statements), as well as the original text, Japanese translation, diagrams, solution code, and pitfalls for each of the 14 questions. In particular, cryptic_sorter is a confusing trap where carelessly adding one condition to the sort will cause one example to fail, and furthermore, the correct answer is reversed depending on the version, so I have written about it in detail.
